# Проверка и выпуск

Все указанные пути ниже от `assets/projects/`. Архивные команды сначала прочитай и адаптируй к текущему проекту и окружению. Они не запускаются от одного подключения SynthCreator.

| Уровень | Исходный пример | Что он доказывает |
|---|---|---|
| DSP/presets | `PowerKick/Tests/PowerKickTests.cpp`, `PowerBass/Tests/PowerBassTests.cpp` | Проверенные инварианты движка/библиотеки при заданных условиях |
| Wrapper | `PowerKick/Tests/WrapperTests.cpp`, `PowerBass/Tests/WrapperTests.cpp` | MIDI, state, PDC, mono bus и часть GUI/пресетов через процессор |
| Независимый установленный AU | `PowerBass/Tools/sound_audit/main.cpp`, `audit.py`, `CMakeLists.txt` | Сигнал именно загруженного установленного AU, не просто тестового движка |
| Нормировка/повторные пики | `PowerKick/Tools/normalize_peaks.py`, `PowerBass/Tools/normalize_peaks.py`, DSP tests | Пики по конкретной музыкальной сетке; нормировка изменяет пресеты |
| Windows host | `PowerBass/Tools/host_check/` | Загрузка VST3, звук, state, GUI lifecycle в доступной Windows/Wine-среде |
| Установка/удаление под Wine | `PowerBass/Tools/host_check/win_install_test.sh` | Конкретный silent installer, содержимое, загрузка и удаление в изолированном Wine prefix |
| Формат хоста | auval / pluginval | Формат и поведение, охваченное валидатором; не музыкальное качество |
| Слух и workflow | Реальный проект DAW, оценка пользователя | Пригодность звука и поведения в выбранном контексте |

Для новой проверки фиксируй revision, хеш исходников и исполняемого артефакта, preset list, sample rate, block size, ОС/архитектуру, host, MIDI/tempo, commands/exit code и полные первичные логи. Краткая сводка ссылается на них. Если использована рабочая копия с чужими изменениями, изолируй эксперимент либо зафиксируй их без отката.

Матрицу выбирай по риску: 44.1/48/96 kHz и нужные буферы; разные block sizes; точные sample offsets; повторный prepare и state load; моно/стерео; automation; окна и закрытие GUI; хвосты и быстрые повторы. У новой полифонии добавятся собственные сценарии. Не копируй слепо число тестов PowerKick/PowerBass.

Независимая проверка звука: NaN/Inf, DC, silence/tails, sample/true peaks, aliasing по корректно сопоставленным SR, stereo/mono, timing, velocity и pitch, нагрузка. Автоматический детектор «щелчков» по второй разности отмечает также намеренную фактуру — интерпретируй с уровнем и окружением; без слуха не говори «слышимых щелчков нет».

## Сборки и установщики

`PowerKick/CMakeLists.txt` и `PowerBass/CMakeLists.txt` фиксируют JUCE commit. Deployment target macOS задаётся **до project()**; поздняя установка ранее оставляла требование версии build-машины. Проверь реальные load commands/архитектуры артефакта. Это не запуск на старой macOS.

`cmake/patch_juce.cmake` в обоих проектах содержит точечную правку JUCE для зависания Windows GUI при ожидании VBlank в Wine. Повторно проверь необходимость с выбранной версией JUCE, не навязывай старую правку любому проекту.

`PowerBass/Tools/release_plugin.sh` и `Tools/make_installers.sh` — историческая инфраструктура конкретных проектов. Release-скрипт содержит локальные пути, завершение процессов и замену установленных плагинов. Это материал для изучения, не универсальная безопасная команда. Не запускай его для упаковки/проверки самого навыка.

Установщики расположены отдельно от сборок в проектах. Проверяй не только локальную сборку, но содержимое пакета и реально установленную копию. Ad-hoc подпись не равна Developer ID/notarization. Cross-build + Wine не равны запуску на настоящей Windows, тихая установка не доказывает внешний вид всех страниц.

Финальный отчёт указывает каждую реально проверенную платформу, артефакт и ограничение. Наличие успешного скрипта в архиве не является новым PASS.
